## 2. Findings — ranked

Severity: **high** = wrong or unsafe output on a page; **medium** = a behavior defect a
configuration reaches; **low** = hygiene, docs, tooling. Every finding is fixed in this pass
unless marked otherwise.

### High

1. **An unconfigured module injected a broken tag.** `initPageHandler()` registered
   `https://www.googletagmanager.com/gtag/js?id=` and `gtag('config', '')` when neither the
   property nor the parameter held an id: a failing script request and a config call with an
   empty id on every page. Fix: `registerPageScripts()` returns false and logs a notice
   (`Prado::log`, `TLogger::NOTICE`) when no id resolves.
2. **The id was written into the page unescaped.** The id went into the script URL and the
   JavaScript string literal by concatenation, so a parameter value with `'`, `</script>` or
   `&` broke the page or, from an untrusted parameter source, injected script. Fix: the id is
   validated (`MEASUREMENT_ID_PATTERN`, 40 characters), `rawurlencode()`d in the URL, and
   `TJavaScript::quoteString()`ed in the block; options go through `TJavaScript::encode()`.

### Medium

3. **The parameter value was cached into the module.** `getMeasurementId()` wrote the parameter
   into `$_measurementId` on first use, so a later parameter change (a `TDbParameterModule`
   update) or `setMeasurementId('')` had no effect for the process. Fix: the getter reads the
   parameter each time and never assigns.
4. **The module missed the page service when loaded late.** `init()` attached to
   `onInitComplete` unconditionally; a lazily loaded module (PRADO 4.2+) initializes after that
   event and never hooked the service. Fix: `init()` checks
   `TApplication::hasStateFlag(STATE_INITIALIZED)` and hooks the running service at once.
5. **A page without `THead` silently ran without the tag.** Head registrations render only
   through `THead`. Fix: at `TPage::onPreRenderComplete` a page without a head gets the scripts
   at the beginning of the form (`registerScriptFile`, `registerBeginScript`). A callback
   request is skipped there: begin scripts render into a callback response and would run the
   tag a second time. `getIsCallback()` is false before `TPage::run()`, so the check cannot
   live in the `onPreRunPage` handler.
6. **No way to leave a page out.** Consent regimes and admin areas need pages without the tag.
   Fix: `Enabled`, and the `onPreRegisterScript` event carrying the page in a `TEventParameter`
   (PRADO 4.4's stoppable event parameter); a handler that stops it skips the page.
7. **No configuration surface beyond the id.** GA4 deployments commonly need `debug_mode`,
   `send_page_view: false`, `user_id`/cookie settings, Consent Mode defaults, and a first-party
   script host. Fix: `DebugMode`, `SendPageView`, `ConfigOptions`, `ConsentDefaults`, `TagUrl`
   (validated as an absolute http(s) URL, fragments refused; a `?` query is extended with `&`).
8. **Untyped properties, unvalidated setters.** `setMeasurementId()` and
   `setMeasurementIdParameter()` stored whatever they were given (`null`, an array, an object).
   Fix: typed private properties, `TPropertyValue` coercion in every setter, JSON or array for
   the two option maps with `ganalytics_options_invalid` on anything else, an empty parameter
   name restoring the default.

### Low

9. **Composer metadata.** `extra.bootstrap` (deprecated key), `>=4.2.0` (no upper bound, no
   PHP floor), `version`/`version_normalized`/`notification-url` in the source. See §1.
10. **Configuration example named a nonexistent module id** (`belisoful/GAnalyticsModule`);
    the package name is `belisoful/ganalytics`. Docblock and README examples corrected.
11. **Docblocks.** `@var stirng`, "Google Maps API Key" and "API Key" copied from another
    module, `@link`/`@license` pointing at the framework repository, a `@param TPageService`
    plus `@param mixed $page` on the same method, `@since 0.0.1`. Rewritten to the PRADO
    documentation style.
12. **`$service->isa('Prado\Web\Services\TPageService')`** is a string class check;
    `instanceof TPageService` is the framework's form (`TPluginModule` uses it) and lets
    phpstan see the type.
13. **No tests, no static analysis, no CI, no changelog, a one-line README.** See §1.
14. **`.gitignore`** listed only the php-cs-fixer cache; `vendor/`, `composer.lock`, phpunit
    and build caches were unlisted.

## 3. Framework observations (not this extension's to fix)

- `TPluginModule::init()` tests `getPluginPagesPath() !== null`, but the getter returns
  `false` when the package has no `Pages/` directory, so every plugin module attaches
  `attachPageServiceBehavior` to `onBeginRequest` and answers `onAdditionalPagePaths` with
  `false . DIRECTORY_SEPARATOR . $pagePath` (a root-relative bogus path). Harmless for a found
  page (the handler runs only for a missing page and the path is not a file), but the check
  should be `!== false`/`!== null` against the actual return. Worth a PRADO issue.
- `THead`'s docblock refers to `registerHeadJavaScript`/`registerHeadJavaScriptFile`; the
  methods are `registerHeadScript`/`registerHeadScriptFile`.

## 5. Expansion (same day): GA4 features on PRADO 4.4 seams

Requested after the resync: fuller Google Analytics support built on the framework's own
mechanisms. Each feature and the PRADO seam it uses:

| Feature | PRADO seam |
|---|---|
| `trackEvent()`, `updateConsent()`, `setUserProperties()`, `gtag()`: calls queued for the page and delivered at `onPreRenderComplete` | `TClientScriptManager::registerEndScript()` on a full page; `TPage::getCallbackClient()->callClientFunction('gtag', …)` on a callback (the client resolves `gtag` by name); `THttpSession` (ArrayAccess) for deferred calls across a redirect |
| `GAnalyticsPageBehavior`: `$this->trackEvent(…)` on any page | `TComponent::attachClassBehavior()` on `TPage`; `IClassBehavior` owner injection |
| `UserIdFromUser` | `TApplication::getUser()` (`IUser::getIsGuest()`/`getName()`), `TSecurityManager::getValidationKey()` as the HMAC key |
| `EnabledModes` | `TApplicationMode`, `TPropertyValue::ensureEnum()` |
| `PagePathAsContentGroup` | `TPage::getPagePath()` |
| `AmendCsp` | `TApplication::getModulesByType(THttpHeadersManager::class)` (lazy modules loaded), `THttpHeadersManager::getHeadersByClass()`, `THttpHeaderCsp::getPolicy()/setPolicy()`; the nonce comes free from `TJavaScript` |
| `GAnalyticsMeasurementProtocol`, `sendEvent()`, `getClientId()` | `TApplicationClockAwareTrait` for `timestamp_micros` and client ids (`TMockClock` in tests); `THttpRequest::getCookies()->findCookieByName('_ga')` |
| `AdditionalMeasurementIds`, `DataLayerName` | `TPropertyValue::ensureArray()` with `ARRAY_SKIP_EMPTY` |

Design notes:
- `TPage::getIsCallback()` is false before `TPage::run()`, so call delivery lives at
  `onPreRenderComplete`, where the mode is known; a call after that point is deferred rather
  than lost, since `registerEndScript()` is refused during rendering.
- `THttpHeaderCsp::addPolicy()` replaces (it is an alias of `setPolicy()`), so the module merges
  tokens itself and creates a missing directive from `default-src`, or the browser would lose
  the `'self'`/nonce fallback for that fetch type.
- `attachClassBehavior()` refuses a second behavior under the same name on `TPage`; the module
  attaches once and offers `detachPageBehavior()`. Two module instances in one application
  would collide on `PAGE_BEHAVIOR_NAME`; that is a misconfiguration and surfaces as
  `component_class_behavior_defined`.
- `$http_response_header` is read through `get_defined_vars()` since PHP defines it only after
  a response and phpstan treats it as always defined.

3 clean; phpunit 117 tests, 343 assertions, no deprecations.

Deferred from this expansion:
- A `TShellAction` (`prado-cli ganalytics/send`) for sending Measurement Protocol events from

- Google Signals hosts (`*.g.doubleclick.net`, `*.google.com`) in the CSP sources; they vary by

### Findings from the end-to-end run (fixed)

1. **Head registration on a page without `THead` throws.** `TPage::onPreRenderComplete()` raises
   `page_head_required` when head scripts are registered and no `THead` exists, so the 1.0.0
   "form fallback" could never run. The tag is now armed at `onPreRunPage` and registered at
   `onPreRenderComplete` (`registerTag()`), where the head is known; the fallback registers form
   scripts only.
2. **Deferred calls were lost across a redirect.** `THttpSession::AutoStart` defaults to false and
   `THttpSession::add()` writes `$_SESSION` without starting a session. The store now opens the
   session for a write and, for a read, only when the request carries the session cookie, so a
   visitor gets no session for a lookup that cannot find anything.
3. **Configuration by package name needs an installed package.** `TComposerReflection` reads
   `vendor/composer/installed.json`, which never lists the root project, so the e2e applications
   (and any application inside this repository) configure the module by `class`. Documented.
4. **Browsers hide the `nonce` attribute.** The spec reads the `nonce` property.

### Framework observations (not this extension's to fix)

- `THttpHeaderCsp::init()` calls `TSecurityManager::getCSPNonce()` while the modules initialize.
  That bootstraps the security manager before `onLoadState`; `getValidationKey()` then finds no
  global state, generates a key, and the postback's page state fails validation on the next
  request ("Page state is corrupted") whenever no `ValidationKey` is configured. Reproduced with
  `curl` by toggling the headers manager in the e2e configuration. The nonce itself does not need
  the validation key (`generateRandomKey()` is `random_bytes`), so the CSP header could resolve
  the nonce lazily at send time, or `getValidationKey()` could defer reading the global state
  until `onLoadState`. Worth a PRADO issue; the README tells users to set `ValidationKey`.
- The default `THttpResponse` does not send a `THttpHeadersManager`'s headers unless the response
  module is configured with `HeadersManager="<id>"`; the manager alone (with a CSP header) sets
  the nonce on scripts but emits no header. Documented in the README's CSP section; a
  `THttpHeadersManager` that registers itself with the response on init would remove the step.
